# Releasing Eidak | خطوات إصدار نسخة جديدة

This is the maintainer's checklist for publishing a new version.
Steps marked 👤 **human only** cannot be automated and must not be skipped.

## 1. Prepare | التحضير

1. Make sure `main` is green: the **Tests** workflow passes on Windows and Linux.
2. Update the version in **both** places:
   - `pyproject.toml` → `version = "X.Y.Z"`
   - `hand_gesture_control.py` / installer text, if it shows a version.
3. Move the `CHANGELOG.md` **Unreleased** entries into a new
   `## [X.Y.Z] - YYYY-MM-DD` section, and start a fresh empty Unreleased section.
4. Commit and merge through a pull request as usual.

## 2. Tag | عمل التاج

```sh
git checkout main
git pull
git tag vX.Y.Z
git push origin vX.Y.Z
```

Pushing a `v*` tag starts the **Release** workflow, which:

- runs all three headless test suites on Windows,
- builds `Eidak.exe` with PyInstaller,
- creates a **draft** GitHub release with `Eidak.exe`,
  `UserGuide-AR.pdf` and `UserGuide-EN.pdf` attached.

## 3. Verify the draft | مراجعة المسودة

1. Wait for the Release workflow to finish green. If it fails, fix the
   problem, delete the tag, and start over — never publish a red build.
2. Download `Eidak.exe` from the draft release.

## 4. 👤 Human only: real-hardware test | اختبار بشري على عتاد حقيقي

On a real Windows PC with a real webcam, run the downloaded `Eidak.exe` and check:

- [ ] The app starts and finds the camera without the Python installer.
- [ ] Mouse mode: cursor move, left click/drag, right click, double click, scroll.
- [ ] Video mode: play/pause, seek, volume, speed, fullscreen, close.
- [ ] Emergency stop: slam the real mouse into a screen corner.
- [ ] Unplug/replug the camera mid-run: the app reconnects on its own.
- [ ] Low-light warning appears in a dark room.

**Do not publish if any of these fail.** Fix, bump the patch version, retag.

## 5. 👤 Human only: publish | النشر

1. Edit the draft release notes so they match the `CHANGELOG.md` section.
2. Press **Publish release**. This is the point of no return for the tag:
   the "Latest release" README badge updates automatically.

## Notes

- The PDF user guides are generated by `docs/build_manual.py` and committed
  to the repo; the release attaches the committed files. If a guide changes,
  regenerate and commit the PDFs **before** tagging.
- Never reuse or move a published tag. Mistakes get a new patch version.
